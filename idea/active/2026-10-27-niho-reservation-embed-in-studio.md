# Studio に予約フォームの埋め込みパーツを追加する

状態: 実装済み。公開先での接続と申込の受入検証を進める。

## Goal

Studio で制作したページの任意の場所に「埋め込み」パーツを配置し、NIHO アプリからコピーした埋め込みコードを貼って、公開ページで申込まで動くフォームとして表示する。初回対象は NIHO のドロップインと貸切の予約フォーム。設問、空き状況、料金、回答、予約、決済は NIHO アプリを正本とする。Studio は配置・外観・公開を扱う。

## Current system

- Studio の Kamakura 接続では `insertableBlocks=[]` のため、業務パーツをページへ新規追加できない。既存フォームのキャンバス表示は送信不能の見本であり、貼り付け欄もない。
- ページ文書の保存契約は任意 HTML・script・backend URL・秘密を許さない。公開文書はサイトの Git 履歴に残る。したがってコピーしたコードそのものを文書 props に保存して実行する設計は取れない。
- 現行サイトにはページとフローを固定した NIHO フォーム差し替え処理がある。公開用には iframe の親ページ情報、高さ変更、決済遷移を扱う受け口もあるが、Studio で新しい配置を編集する仕組みにはなっていない。
- NIHO の配布コードは iframe と橋渡し用 script で構成され、URL に公開配布用の署名 token が入る。token は公開サイトの origin と flow に結び付く。Studio の編集画面を親にした通常の公開用 iframe プレビューは成立しない。
- トップの `#contact` には現在「無料のお試し利用」と「最初から有料のドロップイン」の二択を含む旧フォームがある。NIHO のドロップイン埋め込み実装も両者の選択に対応する。NIHO「予約メニュー」の現在のプレビューでは両方を選べる。公開ページでも両方を確認する。

## User journey

1. 編集者は Studio の「追加」から「埋め込み」を選び、トップの `#contact` 内や貸切ページの任意の位置へ置く。
2. パーツの設定欄に NIHO アプリが発行した埋め込みコード、またはその iframe URL を貼る。Studio は提供元とフォーム種別を認識し、表示名、公開先ドメインとの適合、背景、PC・モバイルの幅を示す。
3. Studio のキャンバスにはパーツの大きさとフォーム種別が分かる送信不能の見本を表示する。編集者は配置を調整し、公開サイト側のプレビューで実フォームを確認する。
4. 公開後、訪問者はページ内の NIHO フォームで入力・申込・必要な決済を行う。結果は NIHO アプリの予約／回答に入り、Studio 側に回答データを持たない。
5. NIHO 側で設問や案内を変更した場合、公開フォームに反映される。配布 token の再発行時はサイト管理者が接続設定を更新し、参照する各パーツへ一括反映する。

## Options

| 案 | 操作性 | 実装と保守 | 判定 |
| --- | --- | --- | --- |
| A. HTML・script をそのまま貼る汎用枠 | 貼り付けは簡単 | 文書契約を破り、任意 script の実行、origin 不一致、高さ・決済処理のばらつきが起きる | 採用しない |
| B. 配置できる「埋め込み」パーツ＋提供元別の取り込み | NIHO のコピー操作をそのまま使える。ページ内の位置を自由に変えられる | パーサー、接続設定、公開 renderer が必要。NIHO 以外は提供元を追加して拡張できる | 推奨 |
| C. トップ／貸切に専用フォーム枠を固定 | 初回のみ早い | ページやフォームが増えるたびにコード変更が必要。Studio の埋め込みパーツという主目的を満たさない | 採用しない |

## Recommendation

案 B を実装する。利用者には「コードを貼る」操作を提供し、実行される iframe と連携 script は信頼済みのサイト側コードで生成する。初回に認識する提供元は NIHO の `dropin` と `rental` に限定し、第三者サービスは個別アダプターと許可 origin を加えたときだけ使えるようにする。

### 保存と公開の契約

- 貼り付け時に iframe の `data-niho-embed-src` または `src` から URL を抽出する。HTML の `&amp;` を URL として正規化し、配布コード内の script・style・イベント属性は保存も実行もしない。NIHO の URL 形式、flow、許可 query、token payload の公開先 origin・許可 path を確認する。署名の真正性と有効性は公開先で NIHO が検証するため、Studio では「形式確認済み」と表示する。
- Studio のページ文書には `ManagedEmbed` ブロックの参照 ID と安全な外観設定だけを入れる。URL と token を含む接続設定は Kamakura の trusted host が管理するレジストリに置く。公開されるページ文書やリリース履歴に配布コードを混ぜない。
- 接続設定の下書きと公開版を分ける。ページの公開 plan で参照 ID・接続設定の版・公開先 origin をまとめて検証し、公開中のページから未公開設定を参照させない。ロールバック時は対応する公開版の接続設定を復元する。token 再発行時は新しい URL を下書きへ貼り直し、ページを再公開する。
- 公開ページが静的 HTML でも動くよう、サイト Worker に公開済み参照 ID だけを解決する同一 origin の読み取り口を設ける。ページの信頼済み script がここから接続設定を取得して iframe を起動する。未公開参照や未許可 origin には URL を返さない。公開配布用 token は訪問者に見える性質のため、秘密としてではなく編集・公開の権限と origin 制約で守る。
- 共通 `niho-web` はブロック配置・参照 ID の検証と編集 UI の汎用契約を持つ。Kamakura の Studio adapter と site host が接続設定の登録・権限・公開・実描画を持つ。NIHO アプリはフォームと予約処理を持つ。
- サイト公開 renderer は参照 ID を接続設定に解決し、信頼済み iframe と橋渡し処理を描く。親ページの origin と path を NIHO に渡し、`postMessage` は送信元 origin と対象 iframe window の両方で照合する。高さ通知を受け、決済先は NIHO／既知の決済先に限定する。live block を読み取り専用 host view が覆わないよう描画優先順位を確認する。
- 公開サイトの CSP に NIHO の iframe を明示的に許可する。NIHO 側の `frame-ancestors` と launch token は公開ドメインに一致させる。Studio のキャンバスに公開用 token を流さず、申込・決済可能な iframe を Studio の origin で起動しない。
- 通常の背景は白を既定とする。透明背景を選ぶ場合は NIHO 側の文字色と配置先の背景が読めることを PC・モバイルで確認する。iframe は幅 100%、高さは NIHO の通知に追従し、読込前の高さを確保する。

### 既存ページへの適用

- トップ `#contact`: 現在の「無料のお試し利用／有料ドロップイン」の区別を維持する。NIHO のドロップインフォームで両方の選択肢、正しい料金、NIHO 内の申込結果を確認できた時点で、旧フォームを `ManagedEmbed` に置き換える。有料だけの状態ではトップの旧フォームを置き換えず、無料体験の受付経路を失わせない。二重送信や同じ目的のフォームの重複表示を避ける。
- 貸切ページ: 貸切用の `ManagedEmbed` を置き、既存の固定フォーム枠と表示が二重にならないよう移行する。
- 既存のページ固定差し替えは、新パーツへの移行後に対象ページごとに停止する。旧ページが残る間は既存の連絡導線を維持する。

### エラー時

- 貼り付け時: 提供元不一致、URL 形式不正、別環境、公開先 origin／path 不一致を区別して表示し、入力したコード全体をログへ残さない。
- 公開時: 参照 ID が未登録なら公開を止める。公開後に設定を解決できない場合は空白の枠だけにせず、申込できないことと連絡先への導線を表示する。NIHO 側で token が失効していないかは公開先で確認する。
- Studio はパーツの接続状態を「未設定／有効／要更新」で示す。実申込に依存する確認は公開先と同じ origin の検証ページで行う。

## Acceptance

- Studio の追加パネルで「埋め込み」を選べ、トップと貸切ページの任意位置へ複数配置・移動・削除・再編集できる。
- NIHO からコピーしたドロップイン／貸切のコードを貼ると、フォーム種別と公開先が識別される。生の script はページ文書で実行されない。
- Studio の保存・再読込・公開・ロールバック後も参照と表示が一致する。公開文書・Git 履歴・ログに配布 URL の token を残さない。
- 公開ページでフォーム入力、日時・料金、申込、必要な決済、高さの変化が動き、回答と予約は NIHO アプリで確認できる。
- トップでは無料のお試し利用と有料ドロップインを明確に区別し、どちらも目的の申込先に届く。貸切は貸切用フォームへ届く。
- PC とモバイルで背景・文字・操作が読め、読み込み失敗時に代替導線が出る。

## 初回の範囲

NIHO のドロップインと貸切フォームを扱う。第三者の iframe は提供元ごとのアダプターと許可設定を追加してから扱う。トップの切替では、無料体験と有料ドロップインの選択肢を公開先で確認する。
