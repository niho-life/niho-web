Refs #112 / #105。オーナーの指定に従い、STUDIOのデザインエディタ全体を視覚・操作の基準とする。2026-10-22に公式ヘルプの実画面と、既存の鎌倉編集画面をブラウザで確認した。STUDIO本体は確認時メンテナンス中だったため、内部動作は推測しない。

用語とコンポーネントの編集入口は [編集画面の用語と構造](editor-terminology.md) を正とする。編集画面の外にあるプロジェクトのダッシュボード（上部のプロジェクト名・公開ドメイン・「デザインエディタ」と、左1列の「ホーム」「サイト機能」のメニュー）は [プロジェクト一覧・ダッシュボードの接続契約](project-views-contract.md) を正とし、編集画面からはダッシュボードへ戻る入口だけを `toolbarStart` に置く。

## 作業領域と操作の位置

画面全体を、左の細いナビゲーション、左パネル、キャンバス、右パネルで占める。外側の製品紹介見出し・大きい余白・独立したNIHOヘッダーは編集時に重ねない。プロジェクトとページの識別、ダッシュボードへ戻る操作は左上に置く。

- 左ナビゲーション: 44pxの列に32pxのボタンと18pxの線画（線幅1.5）を縦に並べる（左パネルの開閉ボタンも同じ。右パネル上段の操作アイコンも18px・線幅1.5にそろえ、線の太さと大きさを混ぜない）。形はSTUDIOの左ナビゲーションと同じ: 追加（3つの塗りの四角と＋）、ページ（折り目の付いた1枚）、レイヤー（最上段を塗った3段）、スタイル（Aと小さな○）、アップロード（フォルダー）、ストック（画像と＋）、接続（2本のつまみ）、コンポーネント（4つのひし形）。開いているツールは小さな灰色の角丸で示し、各ボタンは `aria-pressed` と `aria-label`、視覚的に隠した名前を持つ。素材providerを列挙できるホストだけアップロード・ストック・接続を別ツールにし、できないホストは1つの「アセット」（フォルダー）にまとめる。接続のない機能を動作するボタンとして見せない。
- 左パネル: 252〜280px。上部にページとプロジェクトの文脈、パネル名、必要な追加・検索・折りたたみ操作。内容だけがスクロールする。文脈は「サイト名 / 開いているページ」と、その下に公開パス（テンプレートは「テンプレート」、サイト全体のコンポーネントは「サイト全体のコンポーネント」、コンポーネント本体は「コンポーネント本体」）。起動時はページパネルを開き、現在のページを `aria-current="page"` の行で示す。ページの行は「名前」と「パス」の2段で、状態は札（文字のバッジ）ではなく右端の小さな点で示す（緑＝公開中、灰＝プレビューのみ・未公開、輪郭だけ＝非公開）。文言はホストが `publication` で渡した label と description を優先し、点のツールチップと読み上げ（`aria-label`）に出す。テンプレートはパスの階層に混ぜず、「テンプレート」の見出しの下に並べる（STUDIOがCMSのページを見出しで分けるのと同じ）。
- 中央: 薄い無彩色のキャンバスに白いページを配置する。ページ幅はCSSの実幅、倍率は作業領域への表示だけに使う。
- 下部中央: 白い小さなフローティングツールバーに表示幅、デバイス幅、「編集モード」を配置する。実装済みのbreakpointだけを選択できる。追加説明の大きなバーにしない。
- 右パネル: 約300px。上段に倍率・プレビュー・保存・公開操作（倍率は閉じた状態で「50%」のように数字だけを出す。全体表示は一覧の「全体表示」の項目で、固定の倍率と見分ける）、その下に選択対象、条件スタイル、文脈に応じたタブ、編集項目を置く。保存状態、失敗時の復旧操作、自動保存switchも上段に残し、項目だけがスクロールする。
- パネルの開閉後も、復帰する操作を残す。キャンバスの全体表示は残った領域で再計算する。

## 選択とインスペクター

Basicの埋め込み群の先頭にはBlankを置く。ホストの承認済みregistryが無い場合はカードと詳細selectを「未接続」として操作不可にし、中心の追加経路でも拒否する。既存Blankを選んだ右パネルには理由を出し、編集・削除は維持する。接続時の設定は承認済み項目のselectとアクセシブルなtitleだけで、自由入力URL欄は置かない。編集キャンバスは外部frameを読み込まず、previewへ切り替えた時だけ表示する。

選択は青い輪郭と小さなハンドルで示す。レイヤーは同じ選択に追従し、人が読める内容名とアイコン、階層、展開ボタンを表示する。内部のIDや配列pathを通常の行名にしない。ロックとコンポーネントの区別は視覚とアクセシブルな名前で伝える。

レイヤー行の図形はSTUDIOのレイヤーパネルに合わせる: テキストはT、画像は左上を塗った四角、ボックスは四角、配置したコンポーネントは紫のひし形（業務ブロックは中に点）。niho-webの要素の種類を見分けるため、箇条書き・番号付きリスト・説明リストは3本線、セクション・ヘッダー・フッター・ナビゲーション・メイン領域・補足領域・記事は上辺に線のある四角にする（`data-layer-glyph`）。文字を持たない要素の行名は「セクション」「箇条書き」「リスト項目」など種類の名前で、移動先の一覧でも同じ名前を使う。展開は行の左のシェブロンで、開くと90°回り、`aria-label` は「〜を開く／閉じる」を保つ。行の高さは28px、階層ごとに14px下げる。

右パネルは対象の種類に応じて項目を出す。

| 選択対象 | タブと内容 |
| --- | --- |
| ページ全体 | ページ / サイト。既存のページ情報と公開情報、サイト設定 |
| テキスト | テキスト / ボックス / 変形 / 設定 |
| 画像 | 画像 / ボックス / 変形 / 設定。画像の指定と代替テキストを画像タブへ置く |
| ボックス | ボックス / 変形 / 設定 |
| コンポーネント・業務block | 公開props・表示領域など、実際に編集できる対象を表示 |

モーションは通常/hover/focus/activeの条件スタイルと、変形・時間・遅延・登場の直接編集を使う。「ホバーで少し浮く」などの説明的な独自プリセットメニューを追加しない。未対応のフィルター等を見た目だけ置かない。

4タブはSTUDIOの右パネルと同じ役割にする（#72）。テキスト＝テキストスタイル・文字の見た目、ボックス＝レイアウト・並び・外観・位置、変形＝「トランスフォーム（移動・回転・拡大・縮小・傾き・変形の原点）」→「アニメーション（イージング・時間・遅延。ホバー等の条件スタイルを持つ要素だけ入力できる）」→「登場」の順、設定＝文字の種類・リンク・props・コンポーネント・表示する幅。テキストタブのテキストスタイルと色の候補は、サイト共通スタイルの定義とこのページだけの定義を「サイト共通」「このページ」の見出しで分ける（コンポーネント本体の編集では「サイト共通」「コンポーネント本体」。定義の場所が1つなら見出しを付けない）。

テキストはキャンバスのダブルクリックで直接編集し、枠の外のクリックか⌘Enter（Ctrl+Enter）で確定、Escで取り消す。完了のためだけのボタンは置かず、文字の装飾ツールバーのツールチップと読み上げ用の文で操作を伝える。インスペクターのテキスト欄からも同じ文字を編集できる。

## 見た目と実装の契約

白と薄いグレーを基本とし、本文は黒に近いグレー、補助ラベルは中間グレー。入力は薄いグレーの面、小さな角丸、控えめな境界線。ボタンは小さく、「公開」は青の強い操作にする（owner 決定 2026-10-26・#158）。黒の強いボタンは「作成」「＋ 新しい○○」などの作成系だけに使う。選択色も同じ青に揃える。緑は「公開中」の点だけに使う。

この契約は編集画面だけでなく、Studio の shell・プロジェクト一覧・ダッシュボード・メンバー・CMS・素材・翻訳・アナリティクス・設定にも当てる（#159）。影は使わず、重なる面（メニュー・ダイアログ・浮いた道具）は 1px の枠で分ける。大文字で字間の広い小見出し（kicker）、グラデーションの背景、すりガラス（`backdrop-filter`）、8px より大きい角丸（札とアバターの 9999px を除く）は使わない。

### 配色・角丸・文字のトークン

値の定義は `src/ui-tokens.ts`（`@niho/web/ui-tokens`）の 1 か所だけに置き、各画面の CSS は `var(--nw-*)` だけを使う（#159）。値は STUDIO 社の実測（#158）に合わせる。

- 各画面の CSS（`workspaceCss`・`collectionCss`・`localizationWorkspaceCss`・`projectViewCss`・`projectManagerCss`・`siteAnalyticsCss`・`siteAppsCss`）は先頭にトークンの定義 `uiTokensCss` を持つ。部品を `<style>` で入れるだけで同じ見た目になる。
- Studio は CSP で inline の `<style>` を使えないので、`studio/build.mjs` が `uiTokensCss` を `assets/studio.css` の先頭に足す。全ページが最初に読むファイルなので、`project-view.css`・`collection.css` からは重複するトークンを外して書き出す。
- 定義は `:where(:root)` で詳細度が 0 になる。ホストは `:root` や部品の根で同じ名前を上書きできる。ページの文書のトークン（`--nw-<名前>`）は `[data-nw-scope]` の要素に閉じるので、ここの名前とぶつからない。
- CSS 変数が届かない所（編集キャンバスの iframe の中の選択枠・挿入位置・文字の道具、SVG の線、キャンバスに出すホストの見本）は `uiColor` の値を差し込む。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--nw-bg` | `#fff` | 画面の背景・パネル |
| `--nw-surface` | `#f7f7f7` | 一段沈んだ面（キャンバス・サイドの列・一覧の地） |

### 入力欄のトークン

通常の入力・単位付き入力（`.e-frame`）・URL 入力（`.e-url-input`）・セレクト・テキストエリア・検索欄は、種類を問わず同じトークンだけで描く（#71）。値は変えずに `src/ui-tokens.ts` で定義する。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--e-input` | `#f2f2f2` | 面 |
| `--e-input-border` | `#e3e3e3` | 枠線 |
| `--e-input-disabled` | `#e9e9e9` | 無効・読み取り専用の面 |
| `--e-placeholder` | `#858585` | placeholder（面に対して 3:1 以上を保ち、本文より明確に弱い） |
| `--e-unit` | `#666` | 単位・URL の接頭辞など入力面の上の補助文字 |
| `--e-radius` | `6px` | 角丸 |
| `--e-focus` | 青 | フォーカスリング（2px、offset 2px） |

高さは 30px、内側余白は 5px 8px。セレクトはネイティブの矢印を消し、同じ灰色のシェブロンを右端に描く。白い面・緑がかった灰色・暖色の灰色を入力欄に使わない。

状態は色だけで表さない。無効は `disabled` と not-allowed カーソル、入力途中は破線の枠、無効な値は赤の枠と `role="alert"` の文、この幅で指定している欄（`.e-own`）は青の面に加えて項目名の色と「この幅の指定を解除」ボタン、保存前の変更は点で示す。

フォントはInter/Noto Sans JPが使用可能なら優先し、system UIの日本語フォントへfallbackする。編集画面の通常の操作文字は11〜13px、操作高さは28〜34pxを目安とする。編集画面の外（一覧・設定・CMS・翻訳）の本文は14px、ラベルは12px、補助は11px。装飾的な影・カード・大見出し・長い操作説明を作業領域へ並べない。ツールチップとaria-labelでアイコンを説明する。

全サイトが同じ編集shellを使う。`kamakura`等のサイト名を共通UIのレイアウト種別にしない。hostの入口は汎用のtoolbar slotで渡し、文書・保存・公開・入力中保護・read-only・ロックの意味を保つ。手動保存が必要なadapterでは保存操作を消さない。

CSSは機能別の読みやすい規則へ整理する。既存の巨大文字列へ上書きを積み重ねず、共通tokenとworkspace・rail・panel・toolbar・inspectorの責務を明示する。

右パネルの幅と反映範囲の操作は、短い選択欄へまとめる。現在の大きな色付き説明ボックスや、各入力の下に常時並ぶ継承説明を通常画面へ積まない。反映されない幅を編集中の警告、ロック理由、不正な入力、未確定入力は必要な場面で表示する。継承元・適用範囲の詳細はツールチップとアクセシブルな説明に残す。

workspaceは画面内で高さを分配し、body全体が余分にスクロールしないようmin-heightとoverflowを定義する。狭い画面で編集領域全体を隠して「デスクトップでご利用ください」に置き換えるサイト固有処理は廃止し、共通のパネル開閉で操作を維持する。

shellの高さは `100dvh` が既定で、見出しやバナーを持つホストは `#root>.nw-editor{height:100%}` のように自分のセレクタで高さを渡し、ページ全体をスクロールさせない（`examples/editor-demo.mjs` が例）。1280px以上では左296px（ツール列44px + パネル252px）・右300pxの固定列と `minmax(0,1fr)` のキャンバスで3領域の幅と高さが変わらない。820px以下ではパネルをキャンバスに重ね、480px以下ではインスペクタ上段を折り返して閉じる操作を画面内に残し、表示幅のツールバーを320pxのstageに収める。

## 受入

第3サイトの操作可能なdemoで、ページ全体・テキスト・画像・ボックスの各選択を確認する。レイヤー選択、挿入、階層移動、幅切替、全体表示、条件スタイル、undo/redo、保存・再読込を実際に操作する。狭い画面ではパネル開閉でキャンバスを確保し、操作を失わない。既存の入力中保護と公開確認を回帰確認し、最終画面のスクリーンショットを証跡にする。

## 実装

左レールの「コンテンツ編集」は現在の文書の直接文字を持つ要素を一覧にし、文章検索と選択を提供する。選択すると既存のテキストインスペクタで編集し、保存・履歴・ロック判定は通常の要素編集と共有する。コンポーネント内の文字はその本体を開いて扱う。言語設定の初回 idle / loading は読込中を表示し、明示的な error にだけ再試行を出す。

`PageEditor` はnamed slotを持つサイト共通のworkspace shellを描画する。左の50pxツール列と300pxパネル、中央キャンバス、右の300pxインスペクターを同じ領域に収める。高さは100dvhで確定し、body全体ではなくstageと各パネル内だけをスクロールする。左パネルを閉じても50pxツール列は残り、ツールを選ぶとパネルを開く。ツール列は短い画面で独立スクロールし、方向キー・Home・Endで有効な操作へフォーカスを移せる。フォーカス移動ではパネルを切り替えず、EnterまたはSpaceで操作する。アセットadapterがない等、接続されていない機能のツールは表示しない。コメント・診断・ヘルプのようなホスト側の権限や保存先を要する機能も、接続契約がない間は入口を表示しない。狭い表示ではパネルをキャンバスに重ねて操作を維持する。

キャンバス下部の表示ツールバーは320〜1920pxの数値幅と利用可能な端末幅を扱う。全体表示と25 / 50 / 75 / 100 / 150 / 200%の倍率は右パネル上段に置く。倍率は表示だけに適用し、保存する文書やbreakpointの判定値を変えない。「編集モード」は同じ下部ツールバーからダイアログを開き、PC必須、PC以外はすべて追加・削除可能な段構成と開始幅・プレビュー幅をサイト単位で編集する。PCだけのときも端末ボタンはPCと表示する。ダイアログは最初の閉じる操作へfocusし、Escape、Tabのfocus循環、末尾の閉じる/保存を提供する。読込失敗は再試行でき、競合再読込は編集中の変更を破棄することを明示する。480px以下では下端sheet状にして各行と操作を折り返し、閉じる・保存を画面内に残す。選択枠・挿入位置・リサイズハンドルは青、コンポーネントインスタンスは紫で区別する。

インスペクターのタブは選択対象から決める。画像のURL・アセット・レスポンシブURL・代替テキストは画像タブに置き、ボックスにはテキストタブを出さない。通常 / ホバー / フォーカス / 押下中の条件は選択対象の文脈欄から変更し、条件を選ぶと変形タブを開く。

ホストが編集画面の外側に出す帯（環境の注意・読み取り専用の説明・接続の失敗など）は、保存できない・ロック・不正な入力・接続の失敗のときだけ出し、平常時は出さない。環境（STGなど）は帯にせず、`toolbarStart` に小さな印（`title` と `aria-label` に説明）として置く。

ホスト固有の入口は `toolbarStart` にReact要素を渡す。サイト名によるレイアウト切替は持たず、ExperienceとKamakuraも同じshellを使う。従来の `toolbarLayout` は削除したため、指定していたホストはそのpropを外す。

ローカル確認は `npm run build`、`npm run studio:typecheck`、`npm run studio:build` を実行する。Studio hostの画面確認は `wrangler dev --config studio/wrangler.toml` で起動し、Access認証済みの環境で行う。
