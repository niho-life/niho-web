# Studio 内サイトの編集・公開

## 目的

niho-web は、鎌倉のサイトを Studio で編集・公開するための基盤です。鎌倉の後は、拠点ごとのサイトも同じ基盤で作ります。人は Studio の GUI で文言・画像・サイズ・配置・CMS 記事・SEO 設定を直し、AI は `niho-edit --studio` とファイル同期（`pull`・`push`）で同じサイトを編集します。利用者は数人のスタッフを想定します。

外部のホスト向けの汎用サイトビルダーは目標にしません。スタッフは GUI で、ページの文言・サイズ・配置を自由に直し、要素を足したり動かしたりします。大きなデザインの作り直しと新しい部品の作成は AI も担います。サイトの共通部品で、ページと拠点のサイトの間で使い回す形を目指します（#575）。

## 正本と配信

- Studio がページ・CMS・素材・共通設定の正本です。本文は R2、版と参照は D1 に保存します。
- GUI と `niho-edit --studio` は同じ編集・公開 API を使います。保存した下書きと公開版は分けます。
- 公開時に HTML と SEO 出力を生成して R2 に置き、公開 Worker は保存済みの生成物を返します。
- 公開は生成物をすべて用意してから、現在の公開版を一度だけ切り替えます。サイト全体の復元も公開版の参照先を切り替えて行います。
- 外部 CMS との同期は行いません。予約・問い合わせなどの送信と回答管理は NIHO の埋め込み側が担います。

## 責務

| 部分 | 責務 |
| --- | --- |
| 文書・描画 core | ページ文書の型、検証、HTML / React 描画 |
| Studio | 認証・認可、下書き保存、素材・CMS・共通設定、公開生成 |
| 公開 Worker | host と公開版の解決、保存済み生成物・リダイレクト・404 の返却 |
| NIHO の埋め込み | 予約・問い合わせなど、フォーム送信と回答の管理 |

ページの保存内容に実行コードや秘密を含めません。埋め込み origin はサイト設定の許可リストで制限し、公開時の CSP に反映します。

## 編集と公開の基本

- ページ、CMS 記事、SEO 欄は Studio の日常編集対象です。大きなレイアウト変更は AI が担当します。
- ページの下書きを確認してから、そのページを GUI の公開ボタン 1 回、または `niho-edit --studio publish <page-id>` 1 回で公開します。
- いくつかの変更をまとめて公開する場合は、未公開変更一覧を確認し、GUI または `niho-edit --studio publish --changed` で一度に公開します。
- 公開履歴からサイト全体を戻せます。ページ単位の版履歴と復元も利用できます。
- 全ページの再生成はコード変更や初回移行時に限り、CLI の `publish --all` で行います。日常の GUI には出しません。

詳しい操作と入力形式は [Studio CLI の契約](studio-cli.md) を参照してください。AI がファイルを pull・編集・push する手順は、その機能の実装後に標準手順へ追加します。
